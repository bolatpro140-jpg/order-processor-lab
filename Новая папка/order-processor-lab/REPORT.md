# Отчёт по Уроку 1

## Этап 1. Антипаттерны ответа Copilot на расплывчатый запрос
Запрос: «Напиши функцию для валидации и сохранения заказа в базу данных, чтобы всё работало чисто и без ошибок.»
(Ask, без файлов). Типичные проблемы такого ответа — **заполните по своему фактическому ответу Copilot**:
1. Выдуманные названия полей (`customer_name`, `product_id`, `total_price`), которых нет в проекте.
2. `print()` вместо исключений/логирования для сообщений об ошибках.
3. Нет аннотаций типов, функция длиннее 25 строк, смешаны валидация и запись в БД.
4. Возврат `True/False`/`None` — несовместимо с существующими тестами и сигнатурами.

## Этап 2. Глобальные правила
См. `.github/copilot-instructions.md`. После повторного запроса (с прикреплённым файлом) модель должна
использовать `logging`/`OrderValidationError`, аннотации, декомпозицию и предлагать `ruff check .` + `pytest`.

## Этап 3. Библиотека промптов
`.github/prompts/`: `analyze-legacy` (ask), `write-tests` (edit), `clean-refactor` (edit) — все с YAML `mode` и `description`.
